---
title: "Writing code"
description: "How code is written at Rigiity."
---

- Write clear, readable code with meaningful names. A reader should understand intent without reverse-engineering it.
- Follow the idioms and best practices of the language in use.
- Keep separation of concerns and SOLID structure in mind. Each part should have a job and do it well.
- Comments are welcome when they earn their place: niche context, the reasoning behind a decision, or an explanation of why something was done the way it was. What we avoid is a comment that merely restates what obvious code already says, and code that's commented every other line is more distracting than helpful.
- Prefer a minimal, trusted core. Every dependency is an audit obligation and an attack surface. Build from scratch when it is practical.
- No rushed patches. Small bugs may slip through, but core functionality is always intact at release.
