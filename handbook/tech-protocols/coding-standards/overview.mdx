---
title: "Coding Standards"
description: "How code at Rigiity is written, structured, and reviewed."
---

Code must be reliable and fault-tolerant. We aim for code that keeps working for years, and we get there by building on foundations that have proven themselves: dependencies, runtimes, and protocols with a track record. That's a statement about foundations, not about imagination; unconventional ideas are welcome everywhere else, and chasing them is part of who we are. What we pair with novelty is isolation: the fast-moving parts of a system sit behind clean interfaces, so that when change eventually comes, it's cheap. Deliberate maintenance is part of how we refine; what we refuse is code that demands attention it didn't earn.
